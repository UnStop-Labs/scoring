Problem Statement

How do you fairly rank hundreds of competing models?

The Challenge

  • Satellites see every field — but extracting irrigation status is hard
  • Miners submit radically different model architectures
  • Simple accuracy metrics are gameable (copy another miner's answer)
  • Cross-miner consensus breaks when miners collude
  • Validators need a ground truth they control

v1 Approach (limitations)

✗ Spatial score = cross-miner majority vote
✗ Single weighted sum — no pillar isolation
✗ No baseline gate (even bad models earn rewards)
✗ Soft latency bands, no hard gate
✗ No anti-copy tiebreak
✓ v2: Synthetic deterministic GT
✓ v2: METRIC_REGISTRY (6 pluggable pillars)
✓ v2: Baseline gating (θ = 0.30)
✓ v2: Hard processing-rate gate
✓ v2: Tiebreak by commit block

Ground Truth

Synthetic GT — Deterministic & Ungameable

Inspired by TurboVision's SAM3 Pseudo Ground Truth — a reference the validator controls that miners cannot influence.

# seed = SHA256(nonce + lat + lon + date)
def generate_synthetic_gt(
    nonce, lat, lon,
    query_date, n_cells
):
    seed = _make_seed(nonce, lat, lon, date)
    rng  = _DeterministicRNG(seed)

    # Physics-based seasonal model
    ndvi_base = _ndvi_baseline(lat, doy)
    mi_base   = _moisture_baseline(lat, doy)

    for cell_id in range(n_cells):
        mi  = mi_base + rng.next_range(-0.15, 0.15)
        cls = moisture_class_from_index(mi)
        ...

Physics Model

  • NDVI: Sinusoidal seasonal curve, latitude-tuned (tropics peak 0.55)
  • Moisture: Thai wet season proxy — peaks Aug, troughs Feb
  • Cell noise: Injected deterministically from seed (spatial heterogeneity)
  • Cloud: 5 % cells masked
seed = SHA256(nonce:lat:lon:date) ndvi = base(lat, doy) + A·cos(2π·doy/365) + noise(seed, cell_id)

Two validators seeding with the same nonce produce identical GT — enabling multi-validator consensus checking.

Scoring Engine

# scoring_v2.py
for pillar, weight in element.pillars:
    key    = (element_type, pillar)
    metric = METRIC_REGISTRY[key]

    score  = metric(
        gt_cells   = gt_cells,
        pred_cells = pred_cells,
        **shared_kwargs,
    )
    total += score * weight

acc   = total / sum(weights)
score = element.weight_score(acc)

Pillar 1 · 35 %

Moisture Class AUC-F1

Hungarian Cell Matching

Mirrors TurboVision's _hungarian_f1() for bounding boxes — adapted for a 20-m geospatial grid. 

# Fast path: match by cell_id
shared = set(gt_ids) & set(pred_ids)

# Slow path (shifted grids):
cost = |gt_cell_id − pred_cell_id|
rows, cols = linear_sum_assignment(cost)

# Two strictness levels (like IoU thresholds)
strict_f1  = f1(exact_class_match)
lenient_f1 = f1(within_1_ordinal_step)

score = 0.60 × strict_f1
      + 0.40 × lenient_f1

Pillar 2 · 20 %

Moisture Index MAE

What it measures

The numeric precision of soil-moisture predictions — not just the class label, but the exact moisture_index value [0, 1].

MAE = mean(|gt_moisture_index − pred_moisture_index|) score = max(0, 1 − MAE / 0.35) MAE = 0.0 → score 1.00 (perfect) MAE = 0.18 → score 0.49 MAE ≥ 0.35 → score 0.00

Why separate from class F1?

  • Two miners can agree on "DRY" but one reports 0.22, the other 0.38 — very different irrigation urgency
  • Downstream irrigation scheduling needs accurate numeric estimates
  • Rewards models that output calibrated probabilities, not just categories
Analogous to TurboVision's COUNT pillar — a lenient numeric accuracy check that catches gross over/under-estimation even when class labels match.
Pillar 3 · 15 %

Spectral Validity

Physics Bounds

IndexValid RangePenalty
NDVI[-1.0, 1.0]1.0 per violation
NDWI[-1.0, 1.0]0.6 per violation
moisture_index[0.0, 1.0]0.6 per violation

Cross-Band Consistency

  • NDWI > 0.30 but moisture < 0.20 → penalty 0.40
    (water body without moisture signal — impossible)
  • NDVI > 0.70 but moisture < 0.15 → penalty 0.20
    (dense canopy always transpires)

Cloud Fraction

cloud_fraction = masked_cells / total cloud_penalty = max(0, (CF − 0.30) × 1.5) CF = 0.30 → no extra penalty CF = 0.50 → penalty 0.30 CF = 1.00 → penalty 1.05 → score 0

A miner that cloud-masks > 30 % of cells is either using stale imagery or refusing to provide answers — both are penalised.

Analogous to TurboVision's FALSE_POSITIVE pillar — penalises outputs that violate known physical laws regardless of what GT says.
Pillar 4 · 15 %

False Alarm Rate

Counts cells where miner predicts WET or OPTIMAL but synthetic GT says CRITICAL_DRY or DRY.

false_alarms = cells where: pred ∈ {WET, OPTIMAL} AND gt ∈ {CRITICAL_DRY, DRY} FAPK = false_alarms / area_km² score = max(0, 1 − FAPK / 3.0) 0 false alarms → score 1.00 3 per km² → score 0.00

Why this matters

  • A false irrigation alarm costs a farmer an unnecessary pump run (~$15–80 per event)
  • Downstream crop-monitoring dashboards break when a dry field is reported as flooded
  • Models that blindly predict everything WET can't be caught by F1 alone

Analogy

TurboVision: max(0, 1 − FPPI / 10)
AgriScore: max(0, 1 − FAPK / 3.0)
Same pattern — false detections per spatial unit.

Trend Direction Check

gt_dir = mean_mi(gt_now) − mean_mi(gt_prev) pred_dir = mean_mi(pred_now) − mean_mi(pred_prev) if sign(gt_dir) ≠ sign(pred_dir) AND |gt_dir| > 0.05: score −= 0.20

If synthetic GT says the field is drying out (irrigation ending) but the miner reports it's getting wetter — that's a fundamental temporal misread, not just a classification error.

Pillar 6 · 5 %

Confidence Calibration (ECE)

Expected Calibration Error

Bin predictions into 10 buckets [0,0.1)…[0.9,1.0) For each non-empty bin b: ECE += |b|/N × |accuracy_b − conf_b| score = max(0, 1 − 1.5 × ECE)

A well-calibrated miner reporting 80 % confidence should be correct on 80 % of cells.

Hard penalty:
Reported confidence > 0.85 AND actual accuracy < 0.45 → score = 0
(Over-confident wrong predictions are worse than honest uncertainty)

Why 1.5× multiplier?

  • In farming decisions, false certainty is more costly than acknowledged uncertainty
  • A model that says "I'm 95 % sure this field is WET" but is wrong causes an expensive missed irrigation
  • Encouraging honest uncertainty estimates improves the downstream ensemble quality
Falls back to global confidence_overall scalar when per-cell confidence is unavailable (compatible with v1 miners).

The lower bound (2 s) exists because Planetary Computer STAC API requests have a minimum ~1.5 s round-trip. Any faster → the miner didn't actually fetch satellite data.

Baseline Gate

Score Normalisation & Baseline Gating

Why gate at θ = 0.30?

A naive model that always predicts OPTIMAL for every cell would score ~0.28 just from spectral validity and confidence calibration. Without gating, even lazy miners collect TAO rewards.

acc = weighted_mean(pillar_scores) if acc ≤ θ: score = 0.0 # zero rewards else: score = (acc − θ) / (1.0 − θ) # Examples (θ = 0.30): acc = 0.25 → score 0.00 acc = 0.30 → score 0.00 acc = 0.55 → score 0.36 acc = 0.80 → score 0.71 acc = 1.00 → score 1.00

Effect on reward curve

Below threshold → no rewards (cliff). Above → linearly scaled to [0,1]. Score of 1.0 still means perfect.

Anti-Gaming

Plagiarism Detection & Tiebreak

Layer 1 — Cosine Similarity

Flatten each miner's moisture_index vector and compute pairwise cosine similarity.

similarity(A, B) = dot(vA, vB) / (‖vA‖ × ‖vB‖) similarity > 0.99 → A and B both penalised score × 0.20 (80 % cap)

Layer 2 — Tiebreak by Commit Block

if mean(|mi_A − mi_B|) < 0.03: # Responses are near-identical winner = miner with earlier on-chain commit_block

Why this works

  • If miner B copies miner A's model, every moisture_index prediction is identical → cosine similarity = 1.0
  • The 0.03 threshold catches near-copies that add tiny noise to evade detection
  • Tiebreak to earliest commit = the original model always wins over copies
Mirrors TurboVision
are_similar_by_challenges() + pick_winner_with_tiebreak()
Exact same logic: challenge-level score similarity → commit block tiebreak.
